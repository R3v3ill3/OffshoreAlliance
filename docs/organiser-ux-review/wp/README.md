# Work-package plans

One file per work package, `<wp-id>.md` (for example `wp0.2.md`), written by the planner and approved in writing by the orchestrator before implementation starts. Each file carries, in order:

1. Specification (verbatim from the orchestration prompt) and the appendix sections it cites.
2. Plan: files to change with `path:line` references, new files, schema changes, tests to add, the exact commands that prove the acceptance criteria, risks.
3. Orchestrator approval (dated).
4. Deviations from plan (kept by the implementer).
5. Verification output (raw, pasted by the verifier).
6. Reviewer findings and their resolution.
