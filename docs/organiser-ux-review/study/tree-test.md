# Tree test: the four-tab campaign workspace

Run this **before phase 1 is built** (plan section 8, method paragraph).
Allow 15 minutes.

A tree test evaluates a proposed navigation hierarchy: it assesses "the
findability of resources after you have created your proposed navigation
hierarchy". Card sorting generates an architecture, tree testing evaluates one
(https://www.nngroup.com/articles/tree-testing/ ;
https://www.nngroup.com/articles/card-sorting-tree-testing-differences/).

## How to run it

- **Text only.** No screens, no mockups, no icons, no colour. The participant
  reads a list of labels and points at one.
- Show the top level only. When they pick a top-level label, show that
  label's children. Then ask "is what you were looking for here, or would you
  go back?"
- **No back-channel hints.** Do not react to a wrong choice. Do not say "are
  you sure". Let them go all the way down and let them backtrack.
- Record the path they took and whether they backtracked.

## The tree

From plan section 5.4. Top level:

**Wall chart · People · Activity · Setup · More ▾**

Second level:

| Top-level | Children |
|---|---|
| Wall chart | Wall chart, List |
| People | List, Filters, Bulk actions |
| Activity | assessments, lists, calls, SMS, email, tasks |
| Setup | Who's in, Groups & units, Organisers, Basics |
| More ▾ | Strategic plan, Bargaining, Section plans, Insights, Data fields, Activists & WOCs, Library, Imports |

Every cell above is a label you show the participant, exactly as written. Note
that **List** appears under both Wall chart and People. That overlap is real,
it is what task 10 is there to probe, and you must not resolve it for the
participant by explaining the difference.

## The find-tasks

Phrase every task as a goal. **No word from the tree may appear in a task**, or
the participant is matching keywords rather than finding things. That rules out
plan, list, assessment, organiser, who's in, group, unit, wall chart, activity,
setup, insight, library, import, bargaining, section, data field, call, SMS,
email and task.

Read one at a time. Use 8 to 10 of these.

1. See how a shift is tracking.
2. Change which employers and sites the campaign covers.
3. Add a shift to the campaign.
4. Find out which colleagues are working on this campaign.
5. Send a text message to a set of workers.
6. See what was recorded about individual workers last week.
7. Change the campaign's start date.
8. See how we intend to win this campaign over the next year.
9. Find a document about the agreement.
10. Find every worker at one site who has no phone number recorded.

Task 10 is the discriminator between **Wall chart** and **People**: it is the
one goal that needs filtering and acting on a set of workers rather than
reading the chart. If participants split evenly between the two top-level
labels, the two tabs are not distinguishable by name and one of them should go.

## What to record

Per task, per participant:

| Field | Value |
|---|---|
| Task number | |
| First click (top-level label) | |
| Final destination | |
| Correct or incorrect | |
| Backtracked | yes / no |
| Seconds | |

Decide the correct destination for each task **before** the sessions start,
and write it down. Deciding afterwards turns a wrong answer into a right one.

Report first-click accuracy separately from final accuracy. A tree where
people get there in the end but start in the wrong place is still the wrong
tree.
